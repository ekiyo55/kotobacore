# KotobaCore 分割基準（Tokenizer Karuizawa、FR-010、要件定義書 §14 #1）

Karuizawa 2.4（`core/token/lattice.py`）。ラティス＋Viterbi の一発分割で、辞書語・keep_as_unit 語・動詞／形容詞の組み立て・交ぜ書き複合語などのノード候補から最小コスト経路を選びます。粒度は 2 つで、**意味層（Entity / 感情 / 意図 / RAG）は常に coarse で計算**されます。

## 1. coarse（標準 = 意味単位）

原則: **意味を担う最小単位を 1 語にする。活用は語に含める。サ変は名詞と「する」に分ける。**

| 規則 | 例（入力 → coarse） |
|---|---|
| 活用した動詞・形容詞は 1 語（語幹＋活用語尾） | 東京都に行った → `東京都 / に / 行った`、美味しかったけど高すぎた → `美味しかった / けど / 高すぎ / た` |
| 助動詞連鎖も 1 語 | 食べさせられなかった → `食べさせられなかった`（原形 食べる、活用形 使役-受身-否定-過去） |
| 仮定形も 1 語 | 走ればいい → `走れば / いい` |
| **サ変は 名詞 ＋ する** | 勉強した → `勉強 / した`、ワクワクする → `ワクワク / する`（感情語・評価語の表層一致を守るため） |
| 交ぜ書き複合語は 1 語 | 思い出した → `思い出した`、締め切りを守る → `締め切り / を / 守る` |
| 送り仮名の圧縮形も 1 語（N4 で本則形に正規化） | 申込みと見積 → `申込み / と / 見積`（normalized = 申し込み / 見積もり） |
| 辞書エンティティ・keep_as_unit 語は分割しない | 株式会社山田商事の鈴木です → `株式会社山田商事 / の / 鈴木 / です`、代々木公園 → `代々木公園` |
| 繰り返し記号「々」は漢字扱い | 様々な人 → `様々 / な / 人` |
| オノマトペの反復は 1 語（かな表記ゆれは辞書で吸収） | にゃーにゃー鳴いてる → `にゃーにゃー / 鳴い / てる` |
| 数値は数字と単位を分ける | 2026年4月1日に3億円 → `2026 / 年 / 4 / 月 / 1 / 日 / に / 3 / 億円`（日付・金額は Entity 層が `2026年4月1日` / `3億円` としてまとめる） |
| 接続助詞「ので / けど」は独立 | 美味しかった**けど** → `けど`。ただし「〜たので」は動詞に結合することがある（既知の癖、N4 は接続ラベルとして扱う） |

既知の癖（人手評価セットで確認、`tools/quality_test/annotated/review_sheet_v1_verdict.md` の tok 分類 48 件）:

- 動詞＋てる／ても が分かれる（鳴い / てる、聴いて / も）
- 複合名詞の一部が分かれる（スクランブル / 交差点、学習 / コスト）
- 副詞 別に・いや・うーん が文字単位に割れることがある
- 小数・版番号・桁区切り（1.8、2.3.0、5,000）は数字と記号に分かれる（Entity 層で PRODUCT コードは救う）
- 「〜たので」の結合（走ったので → 1 語）

## 2. fine（LM 語彙用）

`Analyzer(granularity="fine")` / `tokenize(text, granularity="fine")`。**組み立てノード（動詞・形容詞・交ぜ書き複合語）だけを 語幹 / 送り仮名 / 活用語尾 に分解**し、辞書エンティティ・keep_as_unit・サ変名詞・数値はそのままです。1 トークンあたり約 1.45 字（坊っちゃん全文、coarse は 2.02 字）。

| 入力 | coarse | fine |
|---|---|---|
| 東京都に行った | 東京都 / に / 行った | 東京都 / に / **行 / った** |
| 思い出した | 思い出した | **思 / い / 出 / した** |
| 締め切りを守る | 締め切り / を / 守る | **締 / め / 切 / り** / を / **守 / る** |
| 食べさせられなかった | 食べさせられなかった | **食 / べ / さ / せ / ら / れ / なかった** |
| 走ればいい | 走れば / いい | **走 / れば** / いい |
| 株式会社山田商事 | 株式会社山田商事 | 株式会社山田商事（辞書語は不分割） |

fine の POS は `動詞-語幹` / `動詞-活用語尾` / `形容詞-語幹` などになり、`dictionary_form` は全体ノードの原形を語幹側に持ちます。Vocab モジュール（`kotobacore.vocab`）はこの fine 出力から語彙表を作ります。

## 3. 判断基準の優先順位（ラティスのコスト）

1. keep_as_unit 語（辞書の `keep_as_unit=true`、評価語、優先複合助詞）— ほぼ絶対優先
2. 辞書語（感情 / スラング / 評価語 / エンティティ / エイリアス / 送り仮名変異形）— 軽い優遇
3. 組み立てノード（漢字語幹＋送り仮名、交ぜ書き複合語、ひらがな形容詞活用）— 長いほど有利、ただし語幹の漢字数が多いほど不利
4. 既知のひらがな語（代名詞・副詞）
5. 文字種の連続（漢字列・カタカナ列・数字列）
6. 名詞→名詞・同一助詞連続の接続コスト（すもももももももものうち を解く bigram コスト）

分割結果が変わる変更では `core.token.TOKENIZER_VERSION` を上げます（§8）。回帰は `tests/test_golden_set.py`（36 文）と `tests/test_lattice.py`、人手評価セットの分割 F1（現行 0.90）で確認します。

## 4. 他の分割基準との関係（§14 #1 の決定）

Sudachi の A/B/C 短単位や IPADIC の形態素単位は採りません。人手評価セット 100 文の境界 F1 で coarse 0.894、SudachiPy C 0.875、janome 0.865（`tools/benchmark/baseline_comparison.md`）。短単位が必要な用途は fine か、Karuizawa 互換 API（`kotobacore.compat`）の TokenMode を使ってください。
